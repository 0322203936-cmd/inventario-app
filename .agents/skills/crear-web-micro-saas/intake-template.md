# Intake — the few things worth asking (tool webs need even less)

Most sessions need **zero or one** question: the archetype catalog answers the
tech, the recipes answer the libraries, and you decide design yourself.

## First, route (don't ask yet)

Read the request against the routing table in `SKILL.md`. Connect, publish,
edit and verify asks need **no** intake. Reserve questions for a **build**
with a thin brief.

## For a build — ask at most these, once

Only the ones not already answered by their message:

1. **Which tool** — only if they said "hazme una web herramienta" without
   naming one. Offer 2–3 catalog picks matched to their situation (see 🎯 in
   `02-microsaas-catalog.md`), don't recite all 25.
2. **Niche** — the multiplier. "¿Para un público concreto? (restaurantes,
   gimnasios, autónomos…) — nichar la herramienta la hace mucho más fácil de
   posicionar." Default if no answer: general, Spanish.
3. **Brand name** — if not given, propose one and move on.
4. *(only for `calculadora-sueldo`)* Which country's taxes.

Template (Spanish — translate to the user's language):

> Para clavarlo necesito un par de cosas:
> 1. **Nombre** para la herramienta (si no tienes, te propongo yo uno).
> 2. **¿Público concreto?** (p. ej. restaurantes, gimnasios…) — opcional,
>    pero nichar ayuda muchísimo a posicionar.
>
> El diseño, colores y lo técnico lo decido yo.

## Never ask

Palette, fonts, layout, which library, ad placement, "¿quieres que use
WASM?", any tech decision — the recipes and `03-tool-page-design.md` decide.

## After they reply

Acknowledge in one line, then build. Gaps → defaults: language Spanish, niche
general, one page, ad slots as placeholders. Tell them when it's ready —
don't narrate every step.
